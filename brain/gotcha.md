# Brain gotchas: mistakes made, and the rule that stops a repeat
Read this before starting work in a Brain session. Add an entry the moment a mistake or surprising error happens: what happened, why, the rule. Newest at the bottom. Never delete entries; mark them `fixed` instead.

| # | Date | What happened | Root cause | Rule from now on |
|---|---|---|---|---|
| G1 | 8 Oct | `claude mcp add ... -- cmd /c npx ...` saved as `cmd C:/ npx ...` and the server timed out. | Git Bash (MSYS) silently rewrites args that look like Unix paths (`/c` → `C:/`). | On Windows, run commands that pass `/x` flags to Windows programs from PowerShell, or prefix with `MSYS_NO_PATHCONV=1`. Verify with `claude mcp get <name>` (must say Connected). |
| G2 | 8 Oct | `grep package.json` failed with "No such file": I set a path variable but never `cd`'d into it. | The Bash tool resets the working directory between calls; a variable is not a `cd`. | Always `cd "<abs path>" &&` at the start of the same command, or use absolute paths. |
| G3 | 8 Oct | A `find . -path ./*/.git -prune ...` scan errored ("paths must precede expression"). | Unquoted glob `./*/.git` was expanded by the shell before `find` saw it. | Quote every `find -path` / `-name` pattern. Re-run a failed safety scan; never treat a crashed scan as "nothing found". |
| G4 | 8 Oct | Amended the first commit and force-pushed `main` to remove a co-author line. | Followed an attribution default before checking the user's preference. | Our CLAUDE.md says **never rewrite history**. Fix mistakes with a new commit. No `--amend`, `rebase` or `push --force` on anything already pushed. (Current preference: the Claude co-author line is fine.) |
| G5 | 8 Oct | Docs pointed to sections that don't exist (`solution.md §5.2`, `§12`; ablation called `§6` instead of `§7`). | solution.md was renumbered from v1 to v2 and the role files weren't updated. | When a doc's sections move, grep every `§` reference to it (`grep -rn "solution.md\` §"`) in the same commit. |
| G6 | 8 Oct | Some files had Windows CRLF line endings (`official_rules.md`, one JSON). | Files created on Windows. CRLF breaks `.sh` scripts on Ubuntu (`bash\r: not found`). | `.gitattributes` forces LF in the repo. Write scripts with LF; on Ubuntu, if a script errors with `\r`, run `git add --renormalize .`. |
| G8 | 8 Oct | `time.monotonic()` on Windows Python 3.10/3.11 uses `GetTickCount64()`: **15.6 ms resolution**. Python 3.13 uses `QueryPerformanceCounter()` (0.1 µs). | Old CPython Windows clock. | Windows dev venv is **Python 3.13** (`py -3.13 -m venv .venv`). `tests/common/test_clock_log.py` fails on a coarse clock on purpose. Ubuntu (CLOCK_MONOTONIC) is fine on any version. |
| G9 | 8 Oct | Plan-time risk for the **Ubuntu VM**: on a Windows host with Hyper-V/WSL2 on, VirtualBox runs in a slow mode and may hide AVX2 from the guest; VMs usually expose **no RAPL** energy counters; VM audio adds latency. | Virtualization. | In the VM: `grep -o -m1 avx2 /proc/cpuinfo` before any benchmark; `ls /sys/class/powercap` to see if RAPL exists (else Spine labels energy "not joules"); use WAV-in for timing runs; clone with git, never run from a shared/OneDrive folder. Give the VM ≥ 4 vCPUs and ≥ 6 GB so the 2 CPU / 2 GB cgroup inside has room. |
| G10 | 8 Oct | Plan bug: chunker digit-wait guarded only `.,`, so "At 3:45" split into "At 3:" + "45" (caught by w1's test). | Plan code was written without running it. | Treat plan code as a spec, not as tested code: every listed test must be run; workers report deviations. Fixed: guard is `.,:`. |
| G11 | 8 Oct | llama.cpp b11501 treats `n_predict: 0` as 1 generated token with no usable timings (w3 probe). | Server behaviour differs from the plan's assumption. | Prefill uses `n_predict: 1` (`DEFAULT_PREFILL_N_PREDICT = 1`). Re-probe after any llama.cpp upgrade. |
| G12 | 8 Oct | Git Bash failed on one long command with several heredocs ("unexpected EOF"). | Shell quoting of multi-heredoc commands is fragile. | Write files with the Write tool; keep shell commands short. |
| G13 | 8 Oct | A test file written through a Bash heredoc lost backslashes (`\x` became `x`, a syntax error). | Shell quoting on the Bash tool. | Write any file containing backslashes with the Write tool, never a heredoc (same family as G12). |
| G7 | 8 Oct | Plan-time risk, not yet hit: we build on Windows but the judged run is Ubuntu under a cgroup. | Windows timings (TTFT, tok/s, RAM) are not judged numbers. | Every number from Windows is labelled `windows-dev, not judged`. Only Ubuntu-under-cap numbers go in `RESULTS.md` or the deck. |
