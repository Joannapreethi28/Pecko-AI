04. Hackathon Rules
During the 24 Hours
● Live Build Requirement: All core construction, including coding, design, database setup,
model training, and integration, must be carried out entirely within the 24-hour window.
● No Pre-Built Projects: Starting from a previously completed project, template, or
boilerplate solution is strictly prohibited. Any team found using a pre-built working
prototype will be disqualified.
● Open-Source Use: Publicly available open-source libraries, frameworks, APIs, and tools
are permitted, provided the core application logic is developed during the hackathon.
● AI-Assisted Development: Teams may use AI coding assistants and generative AI tools.
However, the team must understand what they built, architecture and implementation of
their solution.
● External Assistance: Teams must not receive development assistance from individuals
who are not part of the registered team. Seeking general technical guidance or using
publicly available documentation is permitted.
● Code & Repository: Teams must maintain their project code in a version-controlled
repository throughout the hackathon. Judges may request access to the repository or
commit history for verification.
● Use of Existing Services: Existing APIs, cloud services, datasets, and third-party tools
may be used where relevant. However, the primary solution and its core functionality
must be developed during the hackathon.
● Originality: All submissions must be the team’s own work. Plagiarised, copied, or
substantially reused projects may be disqualified.
● Submission Deadline: Teams must submit their final project, repository link,
presentation, and any required documentation before the announced deadline. Late
submissions will not be considered for the final evaluation.

05. Submission Guidelines
Every team must submit the following through the submission link:
● Git Repository: Submit the link to a Git repository containing the complete source code
of the solution, along with a clear README explaining the project, setup instructions, and
usage.
● Working Prototype: The submitted repository must contain the working implementation
developed during the hackathon.
● Submission Deadline: All submissions must be completed within 8:00 AM. Late
submissions will require prior approval from the organizers.
● Finalist Advancement: The Top 15 shortlisted teams will advance to the Final Round and
will be required to prepare a presentation for the final pitch.

08. Disqualification Policy and Code of Conduct
Teams can be disqualified at any stage due to these reasons:
● Pre-Built Templates: Starting from a pre-existing working application instead of building
during the 24-hour window.
● No-Show: Failure of the team (or required members) to attend mandatory check-ins,
judging, or final presentations.
● Misconduct: Harassment, abuse, or property damage.
Code of Conduct
● Behave with courtesy, professionalism, and respect toward everyone, harassment,
discrimination, cheating, or damaging venue property will result in immediate
disqualification and removal from the event.
● Plagiarism, cheating, or misrepresentation will not be tolerated.
● Do not damage, misuse, or tamper with venue property, equipment, or facilities.
